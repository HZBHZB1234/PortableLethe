## 1. 目标

做一套** portable / 个人与小组规模**的 Limbus 私服方案：

1. 服务端免 Docker、免 PostgreSQL，单目录部署；
2. 一个桌面 Hub 负责版本、资源、配置、进程、多实例、客户端发布包；
3. 一个可切换服务器地址的 Launcher，登录态按服务器隔离；
4. 服务端支持 DLL 插件 + 用户脚本，管理员可逐用户授予脚本权限；
5. 静态数据**永不编译进程序集**，完全由目录提供；
6. Hub 内部纯 Tauri/Rust，不依赖 C# 或 Python 代码（外部 `dotnet publish` 工具链允许）。

## 2. 三仓库职责

| 仓库 | 语言/框架 | 职责 | 不做 |
|---|---|---|---|
| `PortableOpenLethe` | C# / ASP.NET Core 9 | 游戏服务端、账号、存档、管理 API、插件宿主、脚本引擎、SQLite | 资源下载、版本管理、进程管理 |
| `PortableLethe` | Tauri 2 (Rust) + React | 版本/资源/配置/进程/多实例/客户端包导出 | 游戏逻辑、C#/Python 运行时、Launcher 编译 |
| `PortableLetheLauncher` | Tauri 2 (Rust) + React | 客户端：服务器地址切换、profile、登录、mod 列表、客户端侧管理面板 | 服务端管理、资源同步、游戏本体 |

**ZylarNex** 是官服模组加载框架，**不随 Hub 分发、不进私服 profile**（已确认）。

## 4. 关键决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | SQLite 替代 Postgres，**不做存量数据迁移** | 便携部署；用户确认无迁移需求 |
| D2 | 静态数据**永不嵌入**编译产物，运行时目录读取 | Hub 资源更新能作用于预编译版；编译与数据解耦 |
| D3 | 删除 Discord OAuth，服务端自建本地登录页/API | 小范围本地使用；保留 launcher 交接协议形状 |
| D4 | Hub 纯 Tauri/Rust，内部零 C#/Python | 用户要求；UnityPy → `unityfs` crate 已验证可行 |
| D5 | `dotnet publish` 作为外部工具链允许；Hub 可下载 portable SDK | 用户确认；源码编译通道保留 |
| D6 | Launcher 只分发**预编译**版本，Hub 不编译 Rust | 用户确认 |
| D7 | 管理员逐用户授予脚本权限（`script_grants`） | 用户澄清；`crossAccount` 仅 DLL 插件 |
| D8 | ZylarNex 仅官服用，不分发 | 用户确认 |
| D9 | Hub 管服务端 + 本机客户端 + 导出客户端包 | 用户确认 |
| D10 | Launcher 新增地址切换、管理面板、登录态隔离 | 用户要求 |
| D11 | 资源同步直接使用官方地址/官方模型，无自定义清单协议 | 用户确认；以 ETag/Last-Modified/官方版本判变更 |
| D12 | gh-proxy.com 作为 GitHub 下载加速前缀 | 用户指定；已实测可用 |

## 5. 已验证事实（调研证据）

1. **静态数据当前是嵌入的**：`OpenLethe.Resources.csproj:17-29` + `StaticData.cs:23/45/66/85/101`。改动范围明确。
2. **Launcher 硬编码地址**：本地 Tauri 版 `auth.rs:5`、`downloader.rs` 的 `MANIFEST_URL`/`DOWNLOAD_BASE_URL`/`ADDITIONAL_DLLS`、`news.rs` `NEWS_URL`、`updater.rs` `UPDATE_URL`；`config.rs` 仅 `DisableAutoUpdate`。
3. **`Lethe.cfg` 已有私服配置**：`ServerRoot`（16-19 行）、`CachePath`（36-39）、`IgnoreLauncherToken`（41-44，注释明确"通过官方 launcher 也能登录私服"）。游戏侧无需改插件。
4. **私服 profile 基线**：`LetheLauncher-Distribution-7/` 含 BepInEx core/doorstop/dotnet、`BepInEx/plugins/Lethe.dll`、`ModularSkillScripts.dll`、`motions.dll`、`BepInEx/config/Lethe.cfg`。
5. **Launcher 登录交接形状**：`session_id` → `/auth/login?session_id=...&launcher=true` → 轮询 `/auth/token/poll` → JWT 的 `sub`/`name`/`avatar` 显示在 UI → `lethe-auth.json`。
6. **unityfs Spike（本轮完成）**：见 `04-资源同步与静态数据.md`，2185/2185 逐字节一致。
7. **官方地址**：`api.lethelc.site`（API + 3 个 DLL）、`files.lethelc.site`（manifest/download/news/limbus-manifest.zip/header-password）、官服 CDN `download.limbuscompanycdn.org`。

## 6. 配置所有权边界

依据同一份 `config-schema.json`（语言无关，放 `PortableOpenLethe/config-schema.json`，Hub 读取副本）：

| Hub 拥有（重启生效） | 服务端面板拥有（即时生效） |
|---|---|
| 绑定地址/端口、JWT 密钥与有效期、限流、请求体上限、超时、CORS/FRONTEND_URL、MOD_FILES_DIR、STATIC_DATA_DIR、DB 路径、Plugins 开关与目录、实例 ID | EnableLocalLogin、本地登录方式、Discord 相关残留开关（实际删除）、OPENAI_*、LIMBUS_MANIFEST_URL、发行频道 ID、用户脚本开关 |

两边只读：版本号 / 构建时间 / 健康状态 / 实例状态。

## 7. 总体验收

1. 无 Docker、无 PostgreSQL 的 Windows 机器，Hub 下载预编译服务端并启动，游戏可登录；
2. Hub 同步官服静态数据后重启服务端，新数据生效；
3. 同机模式下全部走 loopback，bundle 缓存不重复下载；
4. 多实例可同时运行、端口/数据互不干扰、资源只存一份；
5. 管理员能在面板逐用户配置脚本权限，用户脚本无法越权；
6. Launcher 可切换服务器地址、登录态隔离；
7. Hub 能导出客户端发布包（不含游戏本体、不含 ZylarNex）。
